# 安读（Anx Reader）同步插件

把 [Anx Reader](https://github.com/anxcye/anx-reader) 的书架、阅读进度与阅读时长从 WebDAV / S3 上读回来，导入本服务器：**书目、阅读进度、每日阅读时长、封面**。

Anx Reader 没有开放同步协议，但它的备份里带一个 SQLite 数据库，书架与阅读记录都在里面。这个插件只**读**那个数据库，绝不改动你的备份。

---

## 一、Anx 在它的备份里留了什么

```
<备份根目录>
├── database7.db          书架、进度、阅读时长都在这个 SQLite 库里
└── data
    ├── cover/<封面图>
    └── file/<书籍原文件>
```

用到的两张表：

| 表 | 一行是什么 | 用到的列 |
|---|---|---|
| `tb_books` | 一本书 | `title`、`author`、`file_path`、`file_md5`、`reading_percentage`、`last_read_position`、`cover_path`、`is_deleted` |
| `tb_reading_time` | 一本书在某一天的阅读秒数 | `book_id`、`date`、`reading_time` |

### 阅读进度：CFI 与百分比

`last_read_position` 是 **EPUB CFI** 串（形如 `epubcfi(/6/458!/4,/70/1:40,/82/1:133)`）。Anx 把 txt / pdf 等格式**先转成 EPUB 再读**（见其 `lib/service/convert_to_epub/`），所以各种格式存下来的都是 CFI —— 插件不需要按格式分支处理。

`reading_percentage` 是 **0-1** 的小数（0.86 = 86%），与 Reeden 的 0-10000 不同。插件会把它换算成服务端约定的 0-1。

### 阅读时长**只有日粒度**（这条最要紧）

`tb_reading_time` 记的是「某本书在某一天读了多少秒」，**没有小时**。

所以这些时长是以「**小时未知**」导进去的：

- 日/周/月趋势、总时长、连续天数：**照常包含**它们；
- 阅读热力图、按小时下钻：**不显示**它们（明细里会标注「时间未知」）。

把日合计硬塞进某个小时是编数据 —— 热力图上会凭空长出一座并不存在的「凌晨高峰」。Anx 官方也没有更细的数据，除非改成每小时跑一次、用两次同步的差值推算上一个小时读了多少（本插件不做这件事）。

### 去重键：直接借用 `file_md5`

`tb_books.file_md5` 就是书籍文件的**整文件 MD5**，与服务端书库去重用的是同一个值。于是：

- 你在网页端上传过的同一本书，Anx 里的阅读进度会**归到同一本**（服务端按 md5 与文档标识关联）；
- 没有 `file_md5` 的书（导入异常等）用 `md5("anx:<id>")` 派生一个稳定键兜底，不会因此漏掉。

`is_deleted = 1` 的书不导入（用户在 Anx 里删掉的），它们的阅读时长也一并跳过。

### 时长怎么关联到书目

阅读时长是**按书 + 天**导入的，导入时服务端按「文档标识 → **整文件 MD5** → 书名」
找对应的书。Anx 这边文档标识就是 `file_md5`，所以：

- Anx 里新出现的书会先被登记进书库，时长自然挂在它名下；
- **同一本书先由 Reeden（或网页端上传）登记过、md5 相同**时，也会归到那一本 ——
  文档标识两边不一样没关系，md5 是同一个值。这一层回退是必需的，否则时长会挂在
  「未关联书籍」上，而进度却是关联好的，看起来像数据坏了。

## 二、准备工作

1. 确认 Anx Reader 的备份已经同步了出去（Anx 自带的 WebDAV 同步）。
2. 管理员把插件装上、启用。
3. **每个要用的人**在自己账号里填一份配置（设置 → 插件）：备份目录、凭据、数据库文件名。

**不需要**为了它在「存储管理」里建存储条目 —— 连接信息直接填在插件配置里。

---

## 三、安装与配置

```bash
# 打包并安装（在仓库根目录）
cd packages/server/plugins-samples/anx-reader-sync
zip -r /tmp/anx-reader-sync.zip .     # plugin.json 与 index.js 必须在 zip 根部
cd -
readsync plugin:install /tmp/anx-reader-sync.zip
readsync plugin:enable com.readsync.anx-reader-sync
```

也可以在**管理后台 → 插件**里上传 zip、启用。

配置分两层。管理员那边只有两件事：

| 配置项 | 默认 | 说明 |
|---|---|---|
| 自动导入间隔 | 60 分钟 | 填 `0` 表示只手动触发 |
| 每日固定同步时间 | `08:00` | 每天这个点再完整同步一次；留空关闭 |
| 数据库未变化时跳过 | 开 | 先比一次 `database7.db` 的 MD5，一样就不解析 |

其余都在**设置 → 插件**里由每个用户自己填：

| 配置项 | 说明 |
|---|---|
| Anx 数据放在哪 | 「在这里填连接信息」（默认）或「复用已有存储」 |
| 连接方式 | WebDAV / S3 兼容对象存储 / 服务器本地目录 |
| WebDAV 地址、用户名、密码、根目录、允许自签名证书 | 选了 WebDAV 时出现 |
| S3 Endpoint、存储桶、区域、Access Key、Secret Key、对象前缀、path 风格寻址 | 选了 S3 时出现 |
| 本地目录 | 选了本地时出现；**相对** `<数据目录>/storage` |
| Anx 备份根目录 | 上面那个位置之下的备份根；留空表示就是它本身 |
| 数据库文件名 | 默认 `database7.db`（Anx 升级大版本时数字会变） |
| 资源目录名 | 默认 `data`（封面在这里面） |
| 时间戳时区偏移 | 默认 `8`；Anx 的时间戳是本地时间且不带时区 |
| 自动登记缺失的书目 / 导入阅读时长 / 取封面 | 默认都开 |

密码类字段加密落库、只回显掩码；**每个用户只能看到、也只能改自己那份**，导入只会进他自己的账号。

### 为什么没有「导入到哪个账号」这一项

和 Reeden 插件同样的原因：导入的目标账号由服务端在 `ctx.forUser(userId)` 那一刻定死，插件的写入入口里根本没有 `user` 参数。见 [插件开发指南](plugin-development.md#45-按用户配置-scope-user) 与 [Reeden 同步](reeden-sync.md#为什么没有导入到哪个账号这一项)。

## 四、跑一次

三种触发方式，都不必等定时：

| 在哪 | 跑谁 |
|---|---|
| **设置 → 插件 → 立即同步** | **只有你自己** —— 配置里写着你的备份位置，就只同步你的账号 |
| **管理后台 → 插件 → 立即运行** | 所有配置过的账号 |
| `readsync plugin:run com.readsync.anx-reader-sync` | 同上（命令行） |

「设置 → 插件」页面上会显示每个账号上次运行的结果（导入了多少本书、多少条进度、
多少段时长），点完「立即同步」也会直接把这次的结果弹出来。

> 同一个人连着点两次不会重复跑：第一次还在跑的时候，第二次会收到「正在运行中」。

---

## 五、导入之后

- 书目的**文档标识就是 `file_md5`**（没有的话是派生键）。想核对时可以直接和 Anx 备份里的 `tb_books.file_md5` 对着看。
- 阅读进度出现在**书籍详情页**，状态会自动从「未读」推进到「在读」。
- 阅读时长进入**统计**：日/周/月趋势与总时长都包含它；热力图上不显示（见上文「只有日粒度」）。
- 封面来自 `data/cover/`。**只给这次导入新建的书设置封面** —— 你后来自己传过封面的书不会被覆盖。
- 平台标识是 `anx`。想显示成中文名，可在**设置 → 阅读平台**里加一个 id 为 `anx` 的平台。

---

## 六、它为什么可以反复跑

| 数据 | 幂等方式 |
|---|---|
| 书目 | 按 `file_md5` 去重，已存在就复用 |
| 进度 | 走服务端统一同步接口的 upsert，同一文档只保留最新 |
| 时长 | **按天替换**：先删掉该账号 + `anx` 平台 + 这些天的旧行，再写入 |
| 封面 | 只对新建的书设置一次 |
| 整库 | 数据库 MD5 没变就直接跳过（连解析都不做） |

「按天替换」还顺带处理了上游删除：插件记着上次导入过哪些天，这次没出现的天会被清空。

## 七、验证

```bash
cd packages/server
READSYNC_DATA_DIR=./data-anx npx tsx src/scripts/anx-import-check.ts
```

**不需要样本**：脚本自己造一个结构与 Anx 一致的 `database7.db`（含一本没有 `file_md5` 的书、一本已删除的书、跨天时长、一张封面），放进本地存储目录，然后走真实的安装 → 配置 → 导入。它会核对：

- 已删除的书与其时长都不导入；
- 有 / 没有 `file_md5` 的书各自怎么登记；
- 进度按 0-1 换算、进度串原样保留，且百分比按 0-10000 落库；
- 时长全部以「小时未知」入库，**热力图跳过它们但日合计包含**；
- 数据库没变化时跳过一次，变化后照常导入，上游删掉的日期会被清空。

## 八、常见问题

**找不到 database7.db**

「Anx 备份根目录」或「数据库文件名」填错了。Anx 升级大版本时文件名里的数字会变（`database7.db` → `database8.db`），改一下这个字段即可。也可以在存储里浏览确认实际文件名。

**时长比 Anx 里显示的少**

对照的是哪一段？Anx 里按「书」显示的时长与 `tb_reading_time` 的合计可能不同（前者含未落库的会话），本插件只导 `tb_reading_time` 里有的。已删除的书不在导入范围内。

**热力图上看不到安读的时长**

这是设计如此：Anx 只有日粒度。日/周/月趋势与总时长都包含它。

**改了备份位置后没有生效**

配置改完立即生效，下一次定时任务或手动触发就会用新的。但注意「数据库未变化时跳过」是按 MD5 判断的 —— 换了目录但内容相同，照样跳过（这是对的）。

**时长那几行写着「未关联书籍」**

1.0.1 之前有这个 bug：时长只认插件自己传来的书目 id，于是「Reeden 先建过同一本
书、md5 相同」时归不到那本书上（进度却是关联好的，看着像数据坏了）。现在服务端
会按「文档标识 → md5 → 书名」自行找书（见上文「时长怎么关联到书目」）。

**升级插件之后历史数据好像没变**

「数据库未变化时跳过」用的键里带了**导入逻辑版本**：逻辑改过之后键名跟着变，
下一次同步（定时或点「立即同步」）就会完整重跑一遍、按新逻辑刷新历史 ——
时长是**按天替换**的，旧行会被替换掉，关联也随之修正。不需要手工清库。
