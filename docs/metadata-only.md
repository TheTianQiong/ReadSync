# 只登记书目、不上传文件

ReadSync 可以完全不存书：**只记录书籍信息与 MD5，文件留在你自己的阅读器里**。阅读进度同步、阅读统计、书库管理都照常工作。

适合这些情况：

- 服务器在 CDN / 反向代理后面，传大文件总失败，而网络侧的限制你调不了；
- 书籍本来就分散在各个阅读器上，你并不需要服务器再存一份；
- 服务器磁盘小或带宽有限，不想让书库文件占资源。

---

## 一、先明确哪些功能依赖文件

| 功能 | 需要文件吗 | 说明 |
|---|---|---|
| 阅读进度同步（统一接口 / KOSync） | **不需要** | 进度按「文档标识」记录，与文件无关 |
| 阅读时长与各类统计 | **不需要** | 来自同步上报的时长，与文件无关 |
| 书库列表、搜索、筛选、标签、阅读状态 | **不需要** | 全是元数据 |
| 书籍封面、简介、评分等 | **不需要** | 元数据 |
| 下载书籍 | 需要 | 没有文件就没有可下的东西 |
| 版本历史与回滚 | 需要 | 版本就是文件的不同副本 |
| 存储目录浏览 | 需要 | 浏览的是存储上的对象 |

也就是说：**只登记书目，等于放弃了「用本服务器当书库文件托管」这一块，其余全部保留。**

---

## 二、怎么开

### 关闭上传

管理后台 → **站点设置 → 上传限制 → 允许上传书籍文件**，关掉并保存。

关闭后：

- 书库页不再显示「上传书籍」，改为显示「登记书目」；
- 所有上传接口（整体 / 分片 / 预签名直传）一律返回 403，且**在读取请求体之前就拒绝**，不会白传几百 MB；
- 已存在的、带文件的书不受影响，仍可下载。

> 即使不关上传，也可以随时用「登记书目」单独登记某本书 —— 两个入口是并存的。

### 登记一本书

书库页 → **登记书目**，填书名与**文档标识**，保存。

「文档标识」是这里唯一有技术含义的字段，务必填对。

**它不是文件的完整 MD5**，而是 KOReader 的「采样 MD5」：在 12 个固定偏移各读 1KB
拼起来算的（最多 12KB），所以对几 MB 的书也是瞬间算出。

- 在哪看：KOReader 里打开该书 → 菜单「云存储 / 进度同步」处的文档标识，或直接看该书 `.sdr` 目录里的 `partial_md5_checksum`。
- 填错不会报错，只会在用起来之后发现进度没挂上 —— 所以别自己算，照抄。
- 服务端**上传**的书不用填：文件经过服务端，它会自己按同一算法算出来。

> 关联顺序是「文档标识 → 完整 MD5 → 书名」。前两档都精确；书名那一档最脆
> （改名就断、同名会认错），仅供第三方客户端兜底。

其余字段（作者、格式、大小、页数、标签、简介）纯展示用，不填也不影响同步。

## 三、进度是怎么关联上的

```
阅读器上报 progress(document = D)
        │
        ▼
   sync_entries 落库（按 user + document，进度本身一定存下来）
        │
        └─ 顺带找这本书：
             ① books.document_id = D   ← 精确，KOReader 走这条
             ② books.md5        = D   ← 兜底，兼容用整文件 MD5 的第三方客户端
             ③ books.title      = 书名  ← 最脆的兜底，改名就断
        │
        ├─ 找到 → 进度百分比写进这本书，阅读时长也归到它名下
        └─ 没找到 → 进度照常保存，只是不与任何书关联
```

所以文档标识填对了，后面的一切都会自动接上。

## 四、常见问题

**登记时提示「该文件已存在于你的书库中（相同 MD5）」**

同一账号下不能有重复的记录。若这本书之前已经上传过，直接用原来那条记录即可。

**上传的书能收到进度吗？**

能。文件经过服务端时它会按同一算法算出文档标识存下来，不需要你做什么。只有**直传**（预签名）时服务端看不到文件，才由浏览器算好带上 —— 这条路也已自动处理。

**下载按钮不见了**

只登记书目的书没有文件，前端不会给出下载按钮。直接调用下载接口会返回 404 并说明「这本书只有书目信息，没有上传过文件」。

**升级前就存在的书，进度还是关联不上**

修复「文档标识」这件事只对新上传/新登记的书生效 —— 老数据的这一列是空的。
用一条命令补上：

```bash
readsync book:backfill-document-id --dry-run   # 先看会补哪些
readsync book:backfill-document-id             # 真正补
readsync book:backfill-document-id --user alice # 只补某个用户
readsync book:backfill-document-id --force      # 已填过的也重算
```

它分两种情况处理：

- **只登记书目的书**：当初填的就是文档标识，直接搬过来（不发网络请求）。
- **有文件的书**：从存储上按范围读算出文档标识 —— 算法只要 12 个 1KB 窗口，
  所以**只读 12KB，不下载整本书**（本地磁盘、S3 兼容存储、WebDAV 都支持范围读）。

补完不需要重启服务，进度就会开始关联。跳过的一般是文件已从存储上删除。

**以后又想传文件了怎么办**

两条路：把上传开关打开，删掉这条记录后用上传的方式重新添加；或给已有书籍传新版本 —— 但对只登记书目的书，服务端会提示你先删除再上传（因为它没有可写入的存储后端）。

**想恢复成正常上传**

管理后台把「允许上传书籍文件」打开即可，无需改动任何部署配置。

## 五、顺带一提：限流

如果多人共用一个公网 IP（比如一家人、一个小团队），默认的登录限流（10 次/分钟/IP）可能被正常使用撞到，提示「操作过于频繁」。可以整体放宽：

```bash
# .env
READSYNC_RATE_LIMIT_FACTOR=3   # 全部接口的配额 ×3
```
