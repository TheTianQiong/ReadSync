# 只登记书目、不上传文件

ReadSync 可以完全不存书：**只记录书籍信息与 MD5，文件留在你自己的阅读器里**。阅读进度同步、阅读统计、书库管理都照常工作。

适合这些情况：

- 服务器在 CDN / 反向代理后面，传大文件总失败，而网络侧的限制你调不了；
- 书籍本来就分散在各个阅读器上，你并不需要服务器再存一份；
- 服务器磁盘小或带宽有限，不想让书库文件占资源。

---

## 一、先明确哪些功能依赖文件

| 功能 | 需要文件吗 | 说明 |
|---|---|---|
| 阅读进度同步（统一接口 / KOSync） | **不需要** | 进度按「文档标识」记录，与文件无关 |
| 阅读时长与各类统计 | **不需要** | 来自同步上报的时长，与文件无关 |
| 书库列表、搜索、筛选、标签、阅读状态 | **不需要** | 全是元数据 |
| 书籍封面、简介、评分等 | **不需要** | 元数据 |
| 下载书籍 | 需要 | 没有文件就没有可下的东西 |
| 版本历史与回滚 | 需要 | 版本就是文件的不同副本 |
| 存储目录浏览 | 需要 | 浏览的是存储上的对象 |

也就是说：**只登记书目，等于放弃了「用本服务器当书库文件托管」这一块，其余全部保留。**

---

## 二、怎么开

### 关闭上传

管理后台 → **站点设置 → 上传限制 → 允许上传书籍文件**，关掉并保存。

关闭后：

- 书库页不再显示「上传书籍」，改为显示「登记书目」；
- 所有上传接口（整体 / 分片 / 预签名直传）一律返回 403，且**在读取请求体之前就拒绝**，不会白传几百 MB；
- 已存在的、带文件的书不受影响，仍可下载。

> 即使不关上传，也可以随时用「登记书目」单独登记某本书 —— 两个入口是并存的。

### 登记一本书

书库页 → **登记书目**，填书名与 **MD5**，保存。

MD5 是这里唯一有技术含义的字段，务必填对：

> 服务端同步进度时，是拿阅读器上报的**文档标识**与 `books.md5` 比对的
> （见 `sync/service.ts`）。对上了，进度才会挂到这本书上、统计才归到它名下；
> 对不上，进度仍然会记录，只是不会与书库里的这本书关联。

这个文档标识就是阅读器里显示的那个（KOReader 的「文档标识」、同步插件里的 document hash）。填错不会报错，只会在用起来之后发现进度没关联上 —— 所以别随手编一个。

其余字段（作者、格式、大小、页数、标签、简介）纯展示用，不填也不影响同步。

## 三、进度是怎么关联上的

```
阅读器上报 progress(document=D)
        │
        ▼
   sync_entries 落库（按 user + document）
        │
        ├─ 查 books：owner = 你 且 md5 = D
        │
        ├─ 查到 → 进度写进这本书，时长累加到它的统计里
        └─ 没查到 → 进度照常保存，只是不与任何书关联
                     （按书名再匹配一次作为兜底）
```

所以登记书目时 MD5 填对了，后面的一切都会自动接上。

## 四、常见问题

**登记时提示「该文件已存在于你的书库中（相同 MD5）」**

同一账号下 MD5 不能重复 —— 它同时也是秒传的去重键。若这本书之前已经上传过，直接用原来那条记录即可。

**下载按钮不见了**

只登记书目的书没有文件，前端不会给出下载按钮。直接调用下载接口会返回 404 并说明「这本书只有书目信息，没有上传过文件」。

**以后又想传文件了怎么办**

两条路：把上传开关打开，删掉这条记录后用上传的方式重新添加；或给已有书籍传新版本 —— 但对只登记书目的书，服务端会提示你先删除再上传（因为它没有可写入的存储后端）。

**想恢复成正常上传**

管理后台把「允许上传书籍文件」打开即可，无需改动任何部署配置。

## 五、顺带一提：限流

如果多人共用一个公网 IP（比如一家人、一个小团队），默认的登录限流（10 次/分钟/IP）可能被正常使用撞到，提示「操作过于频繁」。可以整体放宽：

```bash
# .env
READSYNC_RATE_LIMIT_FACTOR=3   # 全部接口的配额 ×3
```
