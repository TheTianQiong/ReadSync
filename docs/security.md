# 安全设计说明

本文档解释 ReadSync 的几处关键安全设计，以及它们与需求文档字面表述的差异和理由。

---

## 一、密码：传输用 RSA，存储用 Argon2id

### 需求原文

> 密码通过不对称加密的方式进行存储，私钥存在服务器本地内，用户的密码不可明文传递

### 我们的实现

拆成两件独立的事：

| 环节 | 方案 | 达成的目标 |
|---|---|---|
| **传输** | 前端用服务端 RSA 公钥做 RSA-OAEP(SHA-256) 加密 | 「密码不可明文传递」 |
| **存储** | 服务端用 Argon2id 单向哈希 | 「私钥存在服务器本地」+ 密码不可逆 |

流程：

```
浏览器                          服务端
  │                                │
  ├─ GET /api/system/public-key ──►│  返回 SPKI 公钥 + 指纹
  │◄───────────────────────────────┤
  │                                │
  │  WebCrypto RSA-OAEP(SHA-256)   │
  │  加密密码 → Base64 密文         │
  │                                │
  ├─ POST /api/auth/login ────────►│  用本地私钥（data/keys/private.pem）解密
  │   { ciphertext, encrypted }    │  得到明文 → 立即 Argon2id 哈希比对
  │                                │  明文不写日志、不落库
```

### 为什么存储不用「非对称加密」

需求原文说「密码通过不对称加密的方式进行存储」。**这一条没有按字面实现**，原因是字面实现会显著降低安全性：

1. **非对称加密是可逆的**。如果用 RSA 公钥加密密码后存库，那么持有私钥的服务端（或任何拿到 `data/keys/private.pem` 的攻击者）可以解密出**所有用户的明文密码**。私钥一旦泄露 = 全站密码泄露。
2. **密码存储的正确做法是单向哈希**，使得即使数据库和密钥全部泄露，攻击者也无法还原密码。Argon2id 是当前密码哈希的推荐算法（2015 年密码哈希竞赛冠军，抗 GPU/ASIC 暴力破解）。
3. **哈希是不可逆的，因此不需要「用私钥解密来校验」**——校验方式是「用同样的参数重新哈希一次，比对结果」。

我们保留了需求中真正重要的两条约束：**私钥存放于服务器本地**（`data/keys/private.pem`，权限 0600），**密码不明文传递**（RSA-OAEP 加密传输）。安全目标达成，且避免了可逆存储的固有风险。

> 如果你确实需要「管理员能查看用户密码」的能力（例如企业内部分享账号场景），那本质上要求的是可逆存储 —— 我们不推荐，但如果确有需要，可以基于 `crypto/secret-box.ts` 的 AES-256-GCM 加密盒子另做一个独立字段，而**不要**改动登录密码的存储方式。

### 密码策略

- 长度 8–128，必须含大小写字母与数字（`packages/shared/src/schemas/auth.ts` 的 `passwordSchema`，前后端共用同一份规则）
- Argon2id 参数：`memoryCost=19456`（19 MiB）、`timeCost=2`、`parallelism=1`，符合 OWASP 推荐的最小配置，树莓派等低功耗设备上单次校验约 100ms

## 二、KOSync 协议的「同步密码」

### 问题

KOReader 的 KOSync 协议**固定**发送 `md5(密码)` 作为认证凭据，客户端无法改成 RSA 或 Argon2。而 MD5 早已不适合作为密码摘要 —— 它太快，且彩虹表泛滥。

### 方案

服务端为每个用户单独维护一个 `users.kosyncKey` 字段：

- 注册/改密时默认派生为 `md5(主密码)`，让 KOReader 用户开箱即用；
- 用户可在「设置 → 账号安全 → 同步密码」里**单独设置一个与主密码不同的同步密码**，此后 KOSync 只认这个密码的 MD5。

**建议**：如果你在多个服务用同一个密码，请务必设置独立的同步密码。这样即使 `kosyncKey` 因数据库泄露而暴露，攻击者也无法反推出你的主密码。

### 为什么密码哈希不能直接用于 KOSync

我们不能存 `md5(主密码)` 之外的任何东西，因为协议就是要求客户端发 MD5 —— 服务端必须持有可与之比对的值。这是协议兼容性的硬约束，不是设计缺陷。

## 三、令牌与会话

| 机制 | 设计 |
|---|---|
| **access token** | JWT（HS256），有效期 2 小时，签名密钥由主密钥派生（域分离，与凭据加密密钥不同） |
| **refresh token** | 随机 32 字节，**只存 SHA-256 哈希**；每次刷新自动轮换 |
| **重放检测** | 每个 refresh token 属于一个 `familyId`；若已撤销的 token 被再次使用，说明令牌可能被盗，服务端立即吊销该 family 下所有会话 |
| **强制下线** | `users.tokenVersion` 自增，所有已签发 access token 在下次请求时立即失效（中间件每请求回库校验） |
| **接入令牌** | 第三方阅读器用的 `rs_` 前缀令牌，只存哈希，创建时展示一次 |
| **登录限流** | 10 次/分钟/IP，防止暴力破解 |

## 四、第三方凭据的加密存储

WebDAV 密码、S3 SecretKey、Resend API Key 这类凭据**服务端必须能还原成明文**才能去登录第三方服务，所以不能哈希。

方案：AES-256-GCM 可逆加密（`packages/server/src/crypto/secret-box.ts`）

- 密钥由主密钥经 scrypt 派生（加固定盐做域分离）
- 密文格式 `v1.<iv>.<tag>.<ciphertext>`，带版本号便于将来轮换算法
- 所有响应返回给前端前，敏感字段用 `maskConfig()` 脱敏为 `••••••••`

**主密钥管理**：优先取 `READSYNC_SECRET` 环境变量；未设置时首次启动生成随机 48 字节写入 `data/secret.key`（权限 0600）。

> ⚠️ **主密钥丢失 = 已保存的第三方凭据无法恢复**（需要重新填写）。备份 `data/` 目录时务必包含 `secret.key`。

## 五、上传与文件安全

| 风险 | 防护 |
|---|---|
| 路径穿越（`../../etc/passwd`） | 所有存储 key 经 `assertSafeKey()` 校验；本地驱动 `path.resolve` 后二次确认仍在存储根目录内 |
| Zip Slip（插件包） | 解压前校验每个 entry 路径，拒绝 `..`、绝对路径、盘符 |
| Zip bomb | 限制解压后总大小（50MB）与文件数（500） |
| 超大文件 | 站点级 `upload.maxFileSize` 限制，multipart 流式处理，边传边算 MD5，不整文件读入内存 |
| 危险文件类型 | 扩展名白名单（管理员可在后台配置） |
| 磁盘占满 | 单用户配额 `userQuotaBytes`；上传中转文件用 try/finally 确保清理 |

## 六、其它

- **用户枚举防护**：登录失败统一返回「用户名或密码错误」；忘记密码无论邮箱是否存在都返回相同文案
- **验证码防爆破**：邮箱验证码最多尝试 5 次，超限作废；存储的是 `sha256(code)` 而非明文
- **TOTP 防重放**：记录上次成功校验的时间步 `totpLastTimeStep`，相同步数的验证码不可重复使用
- **管理员自锁防护**：管理员不能删除或禁用自己，避免站点失去唯一的管理员
- **安全响应头**：由 `@fastify/helmet` 设置 CSP、X-Content-Type-Options 等；生产环境的 CSP 禁用了内联脚本
- **反向代理**：`READSYNC_TRUST_PROXY` 默认为 `false`，**只有确实部署在受信代理后才应开启**，否则客户端可伪造 `X-Forwarded-For` 绕过登录限流

## 七、部署检查清单

- [ ] 已设置 `READSYNC_BASE_URL` 为真实访问地址（影响通行密钥）
- [ ] 已通过 HTTPS 暴露（WebCrypto 在非安全上下文不可用，且密码加密依赖它）
- [ ] `data/` 目录已纳入备份，且备份包含 `secret.key` 与 `keys/private.pem`
- [ ] `data/` 目录权限为 `700`，`secret.key` 与私钥为 `600`
- [ ] 若在反向代理后，已正确设置 `READSYNC_TRUST_PROXY=true`
- [ ] 第一位管理员已开启 2FA 或通行密钥
- [ ] 已配置邮件服务（否则忘记密码功能不可用）
- [ ] 定期查看「管理后台 → 审计日志」的异常登录记录
